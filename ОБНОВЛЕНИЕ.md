# 🔄 Как обновить лабораторию

Каркас развивается: добавляются уроки, примеры, уточняются правила. Ваша работа при этом
**не трогается** — обновляется только сам каркас.

## Обновиться (одна команда)

Откройте Терминал в папке лаборатории и выполните:

```
git pull
```

Всё. Помощник в следующем разговоре уже будет работать по обновлённым правилам.

**После обновления запустите проверку согласованности:**

```bash
bash scripts/проверка-каркаса.sh
```

Она смотрит две вещи. Первое — не разошлись ли документы между собой: тот ли файл
настроек называют, не велит ли один документ того, что запрещает другой. Такое
расхождение человек не замечает — каждый файл по отдельности выглядит верным.
Второе — двигался ли номер версии вместе с содержимым каркаса.

**Как читать её ответ.** У строк три уровня, и они различаются адресатом:

| знак | о чём | что делать |
|---|---|---|
| ❌ | ошибка сборки каркаса | скажите команде Арджуны, чинить вам не нужно |
| ❗ | состояние вашей папки | это не поломка, читайте текст строки |
| ⚠️ | проверить не удалось | утверждать нечего; строка говорит, почему |

**Про ❗ подробнее.** Если увидите «на этой машине изменено файлов каркаса» с их
перечнем — это ваши собственные правки в общих файлах. Ничего страшного не
случилось, но следующее обновление на них остановится: `git pull` не станет
затирать вашу работу, он просто откажется идти дальше. Скажите нам, чего вам не
хватило, — и мы внесём это в каркас для всех, а вам не придётся держать правку у
себя. **Файл `VERSION` править не нужно вовсе** — иначе обновление точно упрётся
в конфликт на нём.

**Про ⚠️ подробнее.** Такой ответ значит, что часть проверок выполнить не удалось —
например, каркас взят архивом, а не командой `git clone`, и истории у него нет.
Это не поломка, но и не «всё в порядке»: непроверенное и исправное отсюда
неразличимы, поэтому проверка честно отказывается говорить «зелено».

## Что обновляется, а что — ваше навсегда

| Обновляется из репозитория | Остаётся вашим (git не трогает) |
|---|---|
| `CLAUDE.md`, `PROTOCOL.md` — правила | **`config/lab.local.yaml`** — ваши настройки и имена |
| `config/lab.yaml`, `lab.yaml.example` — заготовка настроек | `coordinators/<ваши>.md` — ваши направления |
| `coordinators/` — четыре заготовки направлений | `notes/` — дневник лаборатории |
| `examples/` — примеры задач | `work/` — все рабочие файлы |
| `lessons/УРОКИ.md` — ОБЩИЙ свод уроков | `lessons/МОИ_УРОКИ.md` — ВАШИ уроки |
| | `INBOX/` — ваши входящие |

Это разделение прописано в `.gitignore` — личное физически не попадает в репозиторий.

> 🔴 **Ваши настройки живут в `config/lab.local.yaml`, а НЕ в `config/lab.yaml`.**
> Первый — ваш, его нет в репозитории. Второй — заготовка, она обновляется вместе с
> каркасом и ваши правки в ней будут перезаписаны.
>
> До 01.09.2026 эта таблица называла здесь `config/lab.yaml` — и была неправа: помощник
> читает только `lab.local.yaml` (см. `CLAUDE.md`). Кто поверил таблице, тот записал имена
> туда, где их никто не читает, и получил конфликт при первом же обновлении. Ошибка
> появилась при переименовании файла в v1.0.1: правка дошла до кода и не дошла до трёх
> документов. Класс известный — «починили в одном месте, а знали о нём в четырёх».

## Какая у меня версия

В файле `VERSION` в корне. Посмотреть точную точку истории:

```
git log --oneline -1
```

## Вернуться к прежней версии (если что-то пошло не так)

Версии помечены тегами. Посмотреть список и откатиться:

```
git tag
```

```
git checkout v1.0.0
```

Вернуться к последней: `git checkout main`. **Ваши файлы при этом не пострадают** — они вне git.

## Если `git pull` ругается на конфликт

Значит вы правили файл, который обновился и у нас. Самое простое — попросить помощника:
скажите ему «при обновлении конфликт в файле X, разберись» — он покажет разницу и предложит,
что оставить. Ничего не удаляйте руками сгоряча.

Чтобы конфликтов не было, держитесь простого правила: **что ваше — то новыми файлами.**

| Можно и нужно | Лучше не трогать |
|---|---|
| `coordinators/<ваше-имя>.md` — свои направления, новыми файлами | четыре заготовки: `library`, `portal`, `infra`, `content` |
| `config/lab.local.yaml` — все ваши имена и настройки | `CLAUDE.md`, `PROTOCOL.md` — общие правила |
| `work/`, `notes/`, `INBOX/` — вся работа | `config/lab.yaml` — заготовка, обновляется |

Заготовки направлений не переименовывайте под себя, а просто **не используйте**: место они
не занимают, а при обновлении не поссорятся. Своё направление — это `coordinators/` плюс
ваше имя файла, и оно ваше навсегда.

Если нужна правка в общих правилах — скажите команде Арджуны, она приедет обновлением всем.

> же время велел копировать туда шаблон под своё направление. Два документа требовали
> противоположного, и оба были в каркасе с первого дня. Правило выше снимает противоречие:
> заготовки общие, ваши файлы — ваши.
