# Пример 2 · «Собрать страницу портала» (свайп-кодинг)

**Как попросить:** «Сделай страницу лекции: заголовок, плеер аудио, текст расшифровки под ним, кнопка "скачать mp3". Стиль — как у остальных страниц портала».

**Что делает помощник:**
1. Пишет реальный код (HTML/CSS/JS) — не мокап, а рабочую страницу.
2. Поднимает её локально, показывает результат — можно открыть в браузере и покликать до того, как что-то уходит наружу.
3. Правит по вашим словам: «шрифт крупнее», «сделай тёмную тему», «кнопка не по центру» — и так по кругу, пока не устроит.
4. По ходу объясняет, что именно сделал и почему (например, почему аудио через `<audio>`, а не сторонний плеер) — не просто выдаёт код молча.

**Нюансы:**
- Это и есть «свайп-кодинг»: вы описываете словами, что должно получиться, помощник пишет и правит код диалогом — писать код руками не обязательно.
- Локальный просмотр — не гейт, экспериментируйте свободно. А вот **публикация на реальный портал (деплой) — только по вашему явному «да»**, даже если страница выглядит готовой.
- Если на странице должны быть образы Божеств — Радхарани среди них быть не может (абсолютный запрет), остальные образы — с вашим финальным утверждением.
- Для сложных страниц (каталог, поиск, форма) стоит сначала обсудить структуру данных с координатором `library`, чтобы портал не разошёлся с каталогом.
